Comprehensive Technical Specification: Event-Driven Reconciliation Platform (V1.0)

1. Executive Summary and Architectural Principles

This document specifies the technical requirements and architecture for a high-volume, dynamic financial reconciliation platform. The system is built on three core principles:

Event-Driven Decoupling: Use Gcloud PubSub to ensure independent scalability and prevent failure cascades between services.

Central Hub as Source of Truth: All normalized transaction data is stored in PostgreSQL (Central Hub) for ACID compliance during matching.

Dynamic Configuration: Operational logic (mapping, matching rules, workflows) is stored as data (in Firestore) and read at runtime, allowing finance users to manage the system without requiring code deployment.

3.2. Raw Data Store (Supabase Storage)

Principle: Immutable archival for audit and compliance.

Process: The Raw Archiver module saves the original, unmodified file/payload immediately upon ingestion. The raw_data_uri linking back to this location is generated and included in the normalized transaction record.
